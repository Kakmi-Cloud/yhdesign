# 01 · 评分任务书（给 AI 评审方）

> 本文件可直接作为提示词 / 系统说明交给 Gemini、Claude、GPT 等评审方。
> 评审方**没有操作网页的能力**：无法点击、滚动、输入、启动本地服务、访问 `localhost`。
> 因此本包已把交互式 React 作品集冻结为静态材料，所有评分所需信息都在包内。

---

## 一、任务

请以专业作品集评审的视角，对**「杨鸿 · 产品设计师作品集 · 项目展示板块（改版后）」**做一次全面、独立、可复核的评分。

你需要：先定义清晰的评分体系（分制、维度权重、各档评分标准、判定依据类型），再逐维度打分并给出总分；每项写明优势、扣分原因与**具体依据**（引用本包文件名、章节、截图编号或 CSS 数值），避免笼统结论；最后按影响程度与优先级列出修改意见，指出最值得保留的亮点、主要问题、建议调整方向与预期改善效果。信息不足处明确标注假设或需补充的材料，不要臆测。

## 二、评审对象的边界（重要）

**只评**：改版后的「项目展示板块」，即用户点开任一项目后看到的那 8 段式、影像驱动的展示页。共 8 个项目（01 心景、02 慢行者、03 实习灯具 / 孔雀石、04 情绪疗愈灯具、05 UI 界面流程、06 模块化木质座椅、07 产品概念设计、08 猫冰），结构完全一致、主题色不同。双端口径：桌面 1256×808、手机 414×896 / DPR 2。

**不评**：桌面复古 OS 首页、简历与能力长页、手机首访项目列表、上一轮「项目文件档案版」、更早的 6 套独立详情页、整个工程的架构与商业化表现。这些不在本包内，也不应据传闻推断。

**本次改版的设计目标**（用于判断"是否达成"，不是评分答案）：以产品本体为绝对视觉主体；大幅削减说明性文字，只留精炼辅助信息；具备高级感与趣味感；打破死板规整排布；强化视觉层次、节奏、对比与冲击力。

## 四、无法点击时的替代依据

- 交互行为逐条列在 `03-视觉版式说明书.md` 第 4 节（打开 / 返回 / INDEX 切换 / 滚动进度条 / 首屏视差 / 入场揭示 / 跟随光标 / 胶片拖动 / hover / 减少动效降级）。**不要因为在静态截图里看不到某交互就判定「不存在」**，先查该清单。
- 截图是真实滚动到各段落视口时的渲染帧，桌面与手机均为 8 个项目 × 8 段全覆盖（128 张）；横向胶片的拖动后内容不在截图内，但帧宽与错位规则在说明书第 2 节。
- PDF 由浏览器打印生成，固定／吸顶元素、混合模式与外链字体可能与在线渲染有细微差异；遇到这类差异请以 `06-视觉证据/` 的真实截图为准。

## 五、建议评分体系（可自行调整，不设标准答案）

建议 **100 分制**。建议至少覆盖以下维度，并补充你认为重要的维度：

| 维度 | 关注点（供参考，不构成结论） |
|---|---|
| 视觉风格 | 色彩体系与一致性、字体系统与混排、跨 8 个项目的视觉统一度、深浅主题适配 |
| 交互操作 | 导航与返回的可达性、状态反馈、易用性、触控目标尺寸、交互趣味性 |
| 版式排版 | 网格与破格、间距与留白节奏、信息层级、双端适配、横向溢出与遮挡 |
| 内容呈现 | 文案精简度与准确性、重点是否突出、叙事是否完整、进展与功能表述是否稳妥、是否有依据 |
| 画面展现 | 图像质量、裁切与适配、产品主体占比、视觉冲击力、图片顺序逻辑 |
| 建议补充 | 无障碍与包容性、技术实现与性能、信息可信度（不臆测 / 有出处）、与改版目标的契合度 |

建议做法：每个维度先分别给桌面分与手机分，再按你声明的权重合成；档位标准（如 90+ / 80–89 / 70–79 / 60–69 / <60）请自行定义并写明。判定依据建议分类标注，例如：E 截图证据、M 计算样式 / 量化值、C 源码或 CSS 数值、D 文档记录的交互实现、T 逐字文案。**未取证的项目只列风险，不扣分。**

## 六、输出格式要求

1. **评分体系**：分制、维度与权重、各档标准、判定依据类型定义。
2. **逐维度打分表**：维度 / 权重 / 桌面分 / 手机分 / 合成得分。
3. **逐维度说明**：每项分别写「优势」「扣分原因」「具体依据」；依据要能回到本包的某个文件、章节、截图编号或 CSS 数值。
4. **总分与档位**。
5. **最值得保留的亮点**（列具体位置）与**主要问题**（按严重程度）。
6. **修改意见**：按影响程度与优先级排序（如 P0/P1/P2），每条写清改什么、为什么、预期改善效果。
7. **假设与需补充材料**：明确列出你的前提假设、以及为了更准确评分还需要什么。

## 七、禁止臆测条款（请严格遵守）

1. **不要把 `04-背景资料与事实口径.md` 里的长段文字算作页面文字量**。该文件是后台资料层全文，改版后的页面只显示 `02` 中列出的极简短句。若误算，会得出与事实相反的「文字堆砌」结论。
2. 不要推断资料中未提供的落地、打样、量产、上线、用户增长、获奖、转化或测试结果。四条指定口径的准确表述见 `04` 第「四条必须由资料确认的指定口径」表。
3. 不要把「功能均可实现」理解为「已量产 / 已上市」；它是功能可行性陈述，各项目 caveat 有对应限定。
4. 03 项目评审表上的手写型号与日期字迹不确定，页面未引用为确定参数；不要据此编造参数。
5. 静态截图 / PDF 中看不到的交互，先查 `03` 第 4 节；不要因无法点击就判定功能缺失。
6. 离线打开 HTML 时 Google Fonts 会回退系统字体，字宽与在线状态略有差异；这属于交付环境限制，不宜直接判为设计缺陷。
7. 未取证项（真机手势与帧率、弱网节流、读屏 / 纯键盘走查、线上 URL / SEO、真实用户反馈、目标岗位 JD、产品原图与渲染源文件）请列入「需补充材料」，**不要因缺失而扣分，也不要假设结论**。
8. 本包**刻意不含任何既有评分结论或他人评分报告**，以保证独立评审。若你从其他渠道看到既有评分，请声明并说明是否受影响。

## 八、已知边界（供写「假设」时引用）

- 作品集为 React 18 + Vite + Tailwind 的本地构建产物；本包是它的静态快照，不含可运行的网站工程。
- 截图口径为无头 Chrome 计算样式与 DOM 统计，非真机实测。
- 图像全部来自作品集原有素材，改版未新增产品图；主视觉段排除线稿与过程图的规则见 `03` 第 5 节。
- 论文《心景》文件名标注「二次修改中」，调研数据按当前版本原文转录；若论文定稿有变动，数据需同步。
- 04 / 02 / 05 / 06 / 07 / 08 项目没有落地确认资料，页面统一写「现有资料为设计过程与成果图」类稳妥表述。
